04

보안 구조

라우트 보호 (Frontend Gate)
/admin 경로는 AdminRoute 컴포넌트가 감싸고 있어, admin이 아닌 사용자가 URL을 직접 입력해도 메인 페이지(/)로 강제 이동됩니다.

/expenses는 페이지 진입 후 DB에서 role을 직접 조회해 participant 또는 admin이 아니면 접근을 차단합니다.
데이터베이스 RLS (Row Level Security)
Supabase의 RLS 정책으로 DB 레벨에서 접근을 이중 차단합니다. 프론트엔드를 우회하더라도 데이터를 읽거나 쓸 수 없습니다.

어드민 쓰기 작업은 DB 내 is_admin() 함수로 검증합니다. profiles는 본인 행만 조회 가능 — 타인의 정보 열람 불가.
XSS 방지 (Cross-Site Scripting)
게시물 본문은 HTML을 그대로 렌더링하는 dangerouslySetInnerHTML을 사용합니다. 악성 스크립트 삽입을 막기 위해 렌더링 전 항상 DOMPurify.sanitize()를 통과시킵니다.

적용 위치: PostDetailPage, FaqPage
자동 로그아웃 (Idle Logout)
useIdleLogout 훅이 모든 페이지에서 실행됩니다. 마우스 이동 · 클릭 · 키 입력이 30분간 없으면 자동으로 Supabase 세션을 종료하고 로그아웃합니다.

로그인 상태를 방치해도 세션이 탈취되는 위험을 줄입니다.
이중 예약 방지 (DB Constraint)
컨설팅 슬롯은 consulting_reservations.slot_id에 UNIQUE 제약이 걸려 있어, 동시에 2명이 같은 슬롯을 신청하더라도 한 건만 DB에 저장됩니다.

Founder's Club도 (session_id, user_id) 조합에 UNIQUE 제약을 적용해 중복 신청을 차단합니다.
어드민 권한 분리 (Least Privilege)
어드민 기능은 프론트엔드 라우트 차단 + Supabase RLS + is_admin() DB 함수, 이 세 겹으로 보호됩니다.

일반 사용자가 어드민 API를 직접 호출하더라도 DB 정책에서 거부됩니다. 이미지 업로드는 10MB 제한을 클라이언트에서 먼저 검사합니다.
