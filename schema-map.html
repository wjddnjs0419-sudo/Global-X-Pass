구글 창구 8기 프로그램 포털 · 백엔드 데이터 흐름 시각화

👤 사용자
profiles
회원 정보
사이트에 가입한 모든 사람의 기본 정보를 담습니다.
PK id — 고유 번호
값 email · name · phone · company
값 role — admin / participant / user
📢 공지 · 이벤트
posts
게시물 (공지 / 행사 / 뉴스레터 등)
어드민이 올리는 공지사항, 행사, 뉴스레터, 커뮤니티 글을 모두 이 테이블 하나에 저장합니다.
PK id
값 title · content (한/영 둘 다)
값 category — notice / event / newsletter…
값 event_date · location · max_spots · status
FK author_id → auth.users
🤝 컨설팅 예약
consultants
전문가 프로필
법률·글로벌·기술 분야 전문가 목록입니다. 어드민이 등록·관리합니다.
PK id
값 name · category · bio · expertise[]
값 is_active — 현재 활성 여부
↓ 이 전문가의 예약 가능한 시간대
consulting_slots
예약 가능한 시간 슬롯
"김변호사 6월 5일 오후 2시" 처럼, 전문가의 특정 날짜·시간대를 하나씩 등록합니다.
PK id
FK consultant_id → consultants
값 slot_date · slot_time · duration_minutes
값 status — available / booked / cancelled
↓ 참여사가 이 슬롯을 예약 신청
consulting_reservations
예약 신청서
참여사가 특정 슬롯을 신청하면 여기에 기록됩니다. 슬롯 1개당 예약 1건만 가능합니다(중복 방지).
PK id
FK slot_id → consulting_slots (1:1 UNIQUE)
FK user_id → profiles
값 description — 신청 사유
값 status — pending / confirmed / rejected
값 admin_note — 어드민 메모
🚀 Founder's Club
founders_club_sessions
파운더스 클럽 세션
소수 정예 창업자 모임. 어드민이 주제·날짜·정원을 설정해 개설합니다.
PK id
값 theme · description
값 max_participants — 최대 정원 (최대 10명)
값 session_date · session_time
값 status — recruiting / closed / completed
↓ 참여사가 선착순 신청
founders_club_applications
파운더스 클럽 신청서
참여사가 세션에 신청하면 여기에 기록됩니다. 1인당 같은 세션에 중복 신청 불가.
PK id
FK session_id → founders_club_sessions
FK user_id → profiles (1인 1신청)
값 message — 신청 메시지
값 status — pending / accepted / rejected
📊 분석 / 로그
page_views
페이지 방문 기록
어느 페이지를 몇 번 봤는지 자동 기록. 30분 쿨타임으로 뻥튀기 방지.
activity_logs
관리자 활동 기록
어드민이 데이터를 추가·수정·삭제할 때마다 자동으로 남는 감사 로그.
💡 주요 사용 흐름 — "이런 순서로 데이터가 움직여요"

🤝 컨설팅 예약 흐름

1
어드민이 consultants에 전문가를 등록
2
어드민이 consulting_slots에 날짜·시간대 추가
3
참여사가 원하는 슬롯 선택 → consulting_reservations에 신청서 생성 (status: pending)
4
어드민이 확정/거절 → status가 confirmed 또는 rejected로 변경

🚀 Founder's Club 흐름

1
어드민이 founders_club_sessions에 주제·날짜·정원 설정 후 개설
2
참여사가 선착순으로 신청 → founders_club_applications에 기록
3
어드민이 수락/거절 → 수락된 인원이 max_participants 초과 시 자동 마감
